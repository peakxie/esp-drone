================================================================================
VISUAL EXPLANATION: SLOW THROTTLE RAMP-UP MOTOR CLIPPING
================================================================================

SCENARIO: User slowly ramps throttle from 0 to flight
          Drone has 15° right tilt (attitude error)

================================================================================
PHASE 1: GROUND PHASE (Throttle Ramping, Thrust < Weight)
================================================================================

Timeline: 0ms to 400ms
Thrust Values: 0 → 50 → 100 → 150 → 200 (all below weight ~230)

During this entire period:
- Rate PID measures roll rate error (drone tilted right, gyro not spinning down)
- Integral keeps accumulating: integ = error × dt + error × dt + ...
- No reset happens (PID only resets when thrust == 0)
- By t=400ms: Integral saturates at maximum (±33.3)

PID Correction Output Over Time:

│        │                    ╱──                          │

│        │         ╱                                       │

At t=400ms: Integral hits limit, output = KI × max_integ = 440 × 33.3 ≈ 14,652

================================================================================
PHASE 2: CRITICAL LIFTOFF MOMENT (t=500ms, Thrust ≈ 230)
================================================================================

Drone attempts to lift off:
  Thrust command: 230 (finally > weight)
  Rate PID output: -14,652 (to correct right tilt)

MOTOR MIXING CALCULATION (Quad-X formation):
  r = roll / 2.0 = -14,652 / 2 = -7,326
  p = pitch / 2.0 = 0
  yaw = 0

  M1 = thrust - r + p + yaw = 230 - (-7,326) + 0 + 0 = 7,556 (OK)
  M2 = thrust - r - p - yaw = 230 - (-7,326) - 0 - 0 = 7,556 (OK)
  M3 = thrust + r - p + yaw = 230 + (-7,326) - 0 + 0 = -7,096 (NEGATIVE!)
  M4 = thrust + r + p - yaw = 230 + (-7,326) + 0 - 0 = -7,096 (NEGATIVE!)

     Or if with different roll error (positive instead):
  
  r = +7,326
  
  M1 = thrust - r + p + yaw = 230 - 7,326 + 0 + 0 = -7,096 → limitThrust() = 0
  M2 = thrust - r - p - yaw = 230 - 7,326 - 0 - 0 = -7,096 → limitThrust() = 0
  M3 = thrust + r - p + yaw = 230 + 7,326 - 0 + 0 = 7,556 (OK)
  M4 = thrust + r + p - yaw = 230 + 7,326 + 0 - 0 = 7,556 (OK)

AFTER limitThrust() CLIPPING:
  M1 = 0          ← STOPPED!
  M2 = 0          ← STOPPED!
  M3 = 7,556      → CLIPPED to UINT16_MAX
  M4 = 7,556      → CLIPPED to UINT16_MAX

================================================================================

Quad-X Motor Layout (top view):
        Front
          ↑
      1 ╱   ╲ 3
       ╱     ╲
      │   O   │  ← Drone center
       ╲     ╱
      2 ╲   ╱ 4

        Rear

AFTER CLIPPING:
      Motor 1: OFF (0)
      Motor 2: OFF (0)
      Motor 3: MAXED (7,556)
      Motor 4: MAXED (7,556)

RESULTING FORCES:
      1:OFF    ╱   ╲ 3:MAX
              ╱     ↑
             │   O   │  Diagonal 3-4 pulls HARD
              ╲     ↑
      2:OFF   ╲   ╱ 4:MAX

Diagonal 1-2 (powered off) vs Diagonal 3-4 (maxed out)
→ HUGE ROLL MOMENT (imbalance × lever arm)
→ Drone rolls violently to left
→ Can't maintain stable lift
→ SLIDES SIDEWAYS instead of lifting straight up!

================================================================================
WHY THIS HAPPENS: THE MATH
================================================================================

1. Slow ramp-up means low thrust for extended period
   - Drone is on ground (weight = 0 vertical accel)
   - But thrust is < weight (drone stays grounded)
   - Low thrust + attitude error → integral accumulates

2. Rate PID with KI=440 is very aggressive
   - Even small errors accumulate quickly
   - Error × 440 = large output
   - Large output × low thrust = motor clipping

3. limitUint16() clips ALL negative values to ZERO
   - Not a soft limit (would saturate and share)
   - Not a symmetric limit (would preserve balance)
   - Hard clip to zero → asymmetric motor disabling

4. Motor mixing is linear distribution
   - M = thrust ± corrections
   - If corrections > thrust, some M become negative
   - Clipping turns them to zero
   - Clipping breaks the balance

5. No anti-windup protection
   - Integral doesn't know it's causing clipping
   - Output saturation doesn't trigger integral reset
   - Integral just keeps growing
